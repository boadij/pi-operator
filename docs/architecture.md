# Architecture

Two independent Pi sessions have separate owners and histories. The source extension serves a same-user Unix socket identified by exact session ID and session file. Pairing is explicitly started with `/operator-pair` in the source UI, which displays a random one-use code for two minutes. The intended Operator enters it through its `/operator-pair` UI prompt; the code is not stored in session content or returned by the bridge. A valid code grants an in-memory capability, after which every send authenticates the exact text, request ID, and target identity. The user confirms each instruction once in Operator. Sends use noninterrupting follow-up delivery, and timeouts are unknown rather than rejected or confirmed. Submission is asynchronous and not a delivery guarantee. Capabilities and replay suppression are in-memory only; neither restart recovery nor exactly-once delivery across restarts is guaranteed.

Socket permissions are private to the user. Context is serialized as attributed text and bounded; historical lookup is exposed as a tool. Non-text content, Windows named pipes, multiple attachments, delivery outboxes, and manual Operator compaction are out of scope. Herdr and tmux are optional; the shell command is the universal fallback.
